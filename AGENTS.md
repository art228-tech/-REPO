# Описание проекта для того, кто будет его дорабатывать

Этот файл — для нейросети или человека, который берёт проект впервые. Здесь то,
чего не видно из кода: зачем всё устроено именно так, какие грабли уже собраны и
почему некоторые решения выглядят странно, но менять их нельзя.

Читать целиком перед первой правкой. Дополнять при каждой доработке — в конце
есть журнал находок.

## Что программа делает

Берёт готовый проект CapCut (шаблон), копирует его и подставляет внутрь новые
материалы: два видеоклипа, озвучку, субтитры. Оригинал шаблона не трогается.
Часть параметров разыгрывается случайно, чтобы ролики отличались друг от друга —
это и есть уникализация. На выходе — готовые проекты в папке черновиков CapCut,
которые пользователь открывает и экспортирует вручную.

Экспорт автоматизировать нельзя: у CapCut нет ни командной строки, ни API.

## Устройство шаблона

Шаблон — обычный проект CapCut. На таймлайне:

- **фон** — клип, растянутый на весь кадр и размытый;
- **наложение** — тот же клип поменьше и резкий, поверх фона;
- таких пар две: короткая (2–4 с) и длинная (9–15 с), встык;
- **озвучка**, **фоновая музыка**, короткие звуки: свуш на стыке, звук стикера,
  звук QR;
- **стикер** — эмодзи с комбо-анимацией;
- **QR** в конце;
- **дорожка субтитров**.

Ничего из этого не задано жёстко по номерам дорожек. `profile.py` определяет роли
по содержимому: фон отличается от наложения размытием, озвучка от музыки —
громкостью и длиной, короткие звуки опознаются по длительности. Так шаблоны с
разной раскладкой обрабатываются одинаково. **Не заменяйте это на «дорожка 0 —
фон»** — шаблоны приходят с телефона и с десктопа, раскладка у них разная.

## Порядок работы

```
assets     берёт очередную озвучку и клипы из папок
asr        распознаёт речь, даёт слова с временами
textalign  подменяет распознанный текст точным из файла сценария рядом
plan       считает длину ролика, точку стыка, случайные параметры
builder    клонирует шаблон и подставляет всё внутрь
subtitles  собирает дорожку субтитров
meta       прописывает проект в списке CapCut
validate   проверяет получившийся черновик
diagnose   снимает слепок субтитров для разбора
```

Точка входа — `batch.run()`. Обычно один набор материалов даёт один ролик. При
настройке «три кадра» одна пара клипов идёт в три ролика, но озвучка у каждого
своя: общие только клипы. Каждый ролик обрезается по своей озвучке и получает свои
случайные параметры — план считается отдельно на каждый.

Клипы выбираются под самую длинную озвучку набора (`batch.widest_slots`), иначе
короткому клипу не хватило бы места. Если такого клипа нет, самая долгая озвучка
откладывается, и набор собирается без неё: терять из-за одной озвучки все три
ролика незачем. Взятые клипы при неудаче возвращаются в пул
(`assets.Pool.give_back`).

| `validate.py` | Самопроверка черновика перед выдачей |
| `diagnose.py` | Сравнение субтитров с шаблоном, слепок для разбора |

## Как запускать

```
python -m pytest tests -q          # тесты, их 175
python -m capcut_uniq gui          # окно
python -m capcut_uniq run --clips ... --voice ... --templates ... --count 5
python -m capcut_uniq doctor       # проверка окружения
```

У пользователя всё запускается через `run.bat`, который зовёт `setup.ps1`: тот
ставит Python, FFmpeg, окружение и модель распознавания. Тяжёлые части лежат в
`%LOCALAPPDATA%\capcut-uniq`, отдельно от папки программы, чтобы переживать
обновление.

## Формат черновика CapCut

Всё добыто разбором настоящих проектов, официального описания нет.

### Файлы проекта

- `draft_content.json` — таймлайн;
- `template-2.tmp` — **его точная копия**, приложение читает и её. Писать надо
  оба, иначе правки могут не примениться. Этим занимается `draft_io.Draft.save`;
- `template.tmp` — пустая устаревшая шкала, к делу не относится;
- `draft_meta_info.json` — имя, пути, длительность, список медиа;
- `video/`, `audio/` — материалы проекта.

При клонировании копируется только нужное (`draft_io.KEEP_FILES`). Раньше
копировалось всё подряд, и вспомогательные файлы со ссылками на прежний таймлайн
порождали пустые проекты-призраки.

### Время

Микросекунды. `units.py` переводит туда-обратно. Границы соседних отрезков
считайте от абсолютных времён, а не как «начало плюс длина»: независимое
округление даёт наложение в микросекунду, и CapCut считает такой черновик битым.

### Координаты

`clip.transform.x` и `.y` заданы в долях **половины** размера кадра: `1.0` —
сдвиг на половину ширины. Поэтому сдвиг на треть ширины записывается как `0.667`.

`clip.scale` — увеличение относительно вписанного размера. Для клипа 16:9 в кадре
9:16 при масштабе `1.0` ширина клипа равна ширине кадра, значит запас картинки по
бокам равен `scale - 1`.

### Текст

Самая коварная часть. Текст лежит **строкой с JSON внутри** в поле `content`:

```json
"content": "{\"styles\":[{...,\"range\":[0,38],\"font\":{...}}],\"text\":\"Слово\"}"
```

Правила:

- `range` считается в символах и должен совпадать с длиной текста;
- **правьте эту строку подстановкой, а не разбором и сборкой заново.** CapCut
  пишет без пробелов, Python ставит пробел после запятых и двоеточий и вдобавок
  сокращает дробные числа: `0.059999998658895493` превращается в
  `0.05999999865889549`. По смыслу то же, байты другие. Для этого есть
  `subtitles.rewrite_content`;
- разбиение по словам лежит рядом в `words`: три массива одной длины — тексты,
  начала и концы в миллисекундах. Между словами вставлены пробелы отдельными
  элементами. Времена должны идти по возрастанию.

### Субтитры: два устройства

Сегмент субтитра ссылается либо **на текстовый шаблон** (`text_templates`), а тот
уже на текст, либо **напрямую на текст** (`texts`). Первое приходит с телефона,
второе появляется после пересохранения на десктопе. `profile._subtitles` понимает
оба, и ломать это нельзя.

**Важно:** пересобранный текстовый шаблон CapCut не рисует. Проверено перебором
на живых роликах: субтитры шаблона без изменений рисуются, обычный текстовый
материал с нашим текстом рисуется, а текстовый шаблон, собранный заново, в кадре
показывает свою заглушку `input text...` — с любыми опознавателями, любыми
словами и любой анимацией. Поэтому по умолчанию субтитр пишется обычным текстовым
материалом (`Config.subtitle_device = "простой"`), а стиль берётся из субтитра
шаблона. Причина отказа текстового шаблона не найдена; для её поиска есть
`variants.py`.

### Шрифты

В шаблонах с телефона шрифт записан путём `/data/user/0/com.lemon.lvoverseas/...`,
которого на компьютере нет. Пока субтитр шёл через текстовый шаблон, это не
мешало: шрифт брался из его ресурсов, где путь настоящий. У обычного текста такой
ссылки нет, и CapCut подставляет свой шрифт — один и тот же везде.

`fonts.py` ищет файл на диске. Корень кэша не угадывается, а берётся из путей,
записанных самим CapCut в черновик. Порядок: записанный путь, если открывается;
шрифт по номеру ресурса, который просит шаблон; шрифт из ресурсов текстового
шаблона. Если своего шрифта нет в кэше — значит его никогда не скачивали на эту
машину, и лечится это тем, что шрифт надо один раз применить в CapCut вручную.

### Опознаватели

CapCut пишет их двумя видами: `8-4-4-4-12` из заглавных букв и цифр (не только
шестнадцатеричных) и обычные UUID. Принимает оба. Формат ни на что не влияет —
проверено перебором.

## Что уже пробовали и чем кончилось

Не повторяйте эти попытки.

| Попытка | Итог |
|---|---|
| Рендер без CapCut, через FFmpeg | Отброшено: пришлось бы повторять все эффекты CapCut |
| Копировать шаблон целиком | Проекты-призраки из-за вспомогательных файлов |
| Менять корневой `id` таймлайна | Пустые вкладки в CapCut, `id` надо оставлять как в шаблоне |
| Собирать текстовый шаблон заново | В кадре заглушка `input text...`, причина не найдена |
| Опознаватели в формате CapCut | Ничего не меняет |
| Занять опознаватели шаблона | Ничего не меняет |
| Отключить интернет, чтобы убрать окно про версию | Без сети CapCut не открывает проекты |

## Версии CapCut

Черновики **CapCut International** не шифруются ни в одной версии — шифрует
только китайская сборка JianYing, начиная с 6.0. Открытым текстом черновики
лежат в диапазоне 6.x–9.x. Начиная с 8.7 приложение читает и зеркало
`template-2.tmp` — мы его пишем.

**10.x брать нельзя:** такие сборки отвергают черновики, записанные извне. На
момент написания последняя версия 9.2.0.3931, десятых ещё нет. У пользователя
заблокировано автообновление заглушкой `update.exe` в папке CapCut.

Старые версии ByteDance отключает со своей стороны — приложение показывает окно
про безопасность и не даёт работать. Это не поломка на стороне пользователя.

## Соглашения по коду

- **Всё по-русски**: сообщения журнала, тексты ошибок, комментарии, названия в
  документации. Имена в коде — по-английски.
- Комментарий объясняет, **почему** так сделано, а не что делает строка. Если
  решение выглядит странным — обязательно напишите причину, иначе следующий его
  «исправит».
- Тесты обязательны на каждое исправление. Имя теста — предложение о том, что
  проверяется. В докстроке теста — зачем это важно.
- Журнал должен отвечать на вопросы пользователя без обращения к разработчику.
  Если пользователь спросил «а точно ли…» — значит в журнале не хватает строки.

## Проверки и диагностика

`validate.check` смотрит черновик перед выдачей: ссылки на материалы, наличие
файлов, наложения, длительности, ключевые кадры, целостность субтитров. Не
прошедший проверку проект не выдаётся как готовый.

`diagnose.compare` сравнивает субтитры ролика с шаблоном поле за полем и
проверяет инварианты. После первого ролика партии кладёт слепок в папку журналов
— по нему можно разбирать поломку, не имея доступа к машине пользователя. Поля,
которые обязаны отличаться, перечислены в `diagnose.EXPECTED_DIFFERENT`; при
добавлении новых намеренных отличий пополняйте этот список, иначе диагностика
начнёт кричать о ложных поломках и заслонит настоящие.

`variants.py` собирает один ролик несколькими способами записи субтитров.
Пригодится, если CapCut снова начнёт вести себя необъяснимо: вместо череды
догадок делается пятнадцать копий, различающихся одной деталью, и пользователь
называет ту, где всё правильно.

## Журнал находок

Пополняйте при каждой доработке: что нашли, почему так, что теперь нельзя ломать.

- **Клонирование по списку.** Копирование всей папки шаблона тащило
  вспомогательные файлы со ссылками на прежний таймлайн — CapCut открывал пустые
  проекты-призраки, показывал «Adapted» вместо 1080×1920 и 30 к/с вместо 60.
  Теперь копируется только нужное, а корневой `id` таймлайна остаётся от шаблона.
- **Байты оформления.** Разбор и сборка JSON внутри строки меняли все байты.
  Правится подстановкой.
- **Времена слов.** Растягивание несовпавшего куска сценария заезжало на
  следующий участок, порядок слов ломался, анимация подписи текст не показывала.
  Плюс сдвиги накапливались, и хвост уезжал за конец озвучки — реплики
  оказывались за пределами ролика и отбрасывались.
- **Микросекунда наложения.** Начало и длительность округлялись независимо.
- **Заглушка `input text...`.** Пересобранный текстовый шаблон не рисуется.
  Обошли переходом на обычный текстовый материал.
- **Один шрифт во всех роликах.** Телефонный путь к шрифту не открывается,
  CapCut подставлял свой. Ищем файл в кэше.
- **Партия вставала из-за одной озвучки.** Нехватка клипа в доли секунды
  считалась концом материалов. Теперь малая нехватка закрывается замедлением
  клипа (до 6%), а неудачная озвучка пропускается.
- **Нарезка затирала сама себя.** Номер клипа начинался с единицы в каждом
  прогоне, повторная нарезка того же видео писала те же имена. Восемнадцать
  прогонов дали 373 фрагмента, а осталось 42. Теперь нумерация продолжается.
- **Сценарий оставался без озвучки.** `.txt` не переносился вместе с `.mp3`, в
  папке копились текстовики-сироты.
- **Три кадра из набора.** Клип шире кадра, по бокам остаётся неиспользованная
  картинка. Сдвиг рамки на треть ширины открывает её, и одна пара клипов идёт в
  три ролика. Сдвиг обрезается по запасу `scale - 1`, иначе за краем клипа
  пойдёт пустота. Общие у роликов только клипы: озвучка, длина и субтитры у
  каждого свои, поэтому план считается отдельно на каждый ролик, а клипы
  подбираются под самую длинную озвучку набора.
