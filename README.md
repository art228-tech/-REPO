# Бот-конструктор приветок

Финальная собранная версия **конструктора Telegram-ботов («приветок»)** —
бота, который позволяет создавать и управлять ботами-приветками, реагирующими
на заявки в каналы (`chat_join_request`) и проводящими пользователя по сценарию
(рулетка / обязательная подписка / сообщения).

Проект перенесён из чата с другой нейросетью и **собран в финальную рабочую
версию**: базовый код + все патчи 4–29, включая редактирование ссылок в шагах
(патч 29). Старая ранняя версия и вспомогательные авто-боты удалены.

## Структура репозитория

```
.
├── bot_constructor/      — ФИНАЛЬНЫЙ код конструктора (это и есть продукт)
├── patches/              — исходные патчи 2–29 (история сборки, для справки)
└── docs/                 — материалы: ТЗ, промпты, полная история чата
```

Рабочий код — в [`bot_constructor/`](bot_constructor/). Папки `patches/` и `docs/`
оставлены как справка/провенанс (в т.ч. полная история чата `docs/chat_history_full.txt`).

## Что внутри конструктора

- Несколько приветок одновременно (каждая со своим токеном), менеджер polling.
- 3 типа шагов: 🎰 рулетка (WebApp), 📢 обязательная подписка (в т.ч. «по заявкам»),
  💬 сообщение (текст/фото/гиф/видео/стикер/копия поста + кнопки + ожидание).
- Спонсоры с проверкой подписки и мониторингом прав (патчи 4–6).
- Цвета кнопок (`style`) и премиум-эмодзи на кнопках (патчи 3, 13).
- Дублирование застрявших шагов + авто-пропуск ОП по таймеру (патчи 22–23).
- Раскладка кнопок, имитация печати, отложенный персистентный старт (патчи 14/16, 19, 20).
- Инвайт-ссылки канала со статистикой (патчи 17, 18, 25).
- Каналы приветки `welcome_channels` с задержкой старта на канал (патч 27).
- Корректная обработка удалённых оригиналов копий ⚠️ (патч 26).
- Анти-PEER_FLOOD в карточке шага (патч 28).
- **🔗 Редактирование ссылок в шагах** — патч 29 (новое).
- Статистика, реф-ссылки, массовая рассылка.

## Запуск на том же токене

Конструктор читает токен из `.env` (`bot_constructor/config.py`). Чтобы поднять
его на **том же токене**, что и прежний бот:

```bash
cd bot_constructor
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env   # BOT_TOKEN=<тот же токен>, ADMIN_IDS=<твой id>, DB_PATH=...
python main.py
```

Полный деплой на VPS (nginx + certbot + systemd, нужно для рулетки) —
см. [`bot_constructor/DEPLOY.md`](bot_constructor/DEPLOY.md).

> Снос прежнего: на сервере остановить старый сервис (`systemctl stop bot`),
> заменить каталог `/opt/bot` этим кодом, перенести/создать `.env` с тем же
> `BOT_TOKEN`, затем `systemctl start bot`. БД `data.db` создаётся при первом
> запуске (схема включает все таблицы патчей).

## Как собиралась финальная версия

Базовый снимок (≈15 мая) дополнен патчами 4–29. Большинство патчей —
скрипты `apply_patchN.py` (текстовые правки кода), применены по порядку из
`patches/README_patch_order.txt`. Часть якорей правилась вручную из-за расхождения
ранней базы с серверной линией кода; код приведён к согласованному виду по ТЗ
(`docs/bot_constructor_TZ.md`) и сверен с поздним снимком. Итог: проект
компилируется, все модули импортируются, юнит-тесты зелёные.

### Известные мелкие пробелы (не влияют на запуск)

- UI-выбор раскладки кнопок «1/2/3 в ряд» при создании message-шага: обработчик
  есть, но клавиатура выбора не восстановлена — раскладка по умолчанию 2 в ряд
  (рендер работает, патч 16 ч.4 применён).
- Выбор «оставить кнопки скопированного поста» при создании шага: извлечение в
  `_orig_buttons` работает, но интерактивный выбор (патчи 7/9/10) в ранней базе
  отсутствовал и не восстановлен. Кнопки в message-шаг можно добавлять вручную.

Эти места при необходимости дочиниваются по `docs/chat_history_full.txt`.
