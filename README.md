# Парсер чатов (Telegram)

Бот-краулер для Telegram. Управляется через бота, парсит чаты от лица
подключённого аккаунта: ставит точку в чат и определяет режим чата —
**капча**, **обязательная подписка (ОП)** или **без ограничений**.

## Как это работает

1. Вы входите в аккаунт Telegram через бота — строкой сессии (StringSession)
   или по номеру телефона (код + при необходимости пароль 2FA).
2. Кидаете боту ссылку(и) на чат(ы): `@username`, `t.me/username`, `t.me/+invite`.
3. Запускаете парсинг. Аккаунт по очереди заходит в чаты и ставит точку `.`:
   - **Капча/антибот** → чат в «плохую базу», пропускается.
   - **Обязательная подписка (ОП)** → чат уходит в «ОП проверенные», а все каналы
     из списка подписки добавляются в очередь как «ОП непроверенные» и тоже
     проверяются (краулер идёт по цепочке ОП — потенциально бесконечно).
   - **Без ограничений** и участников ≥ `MIN_MEMBERS` (по умолчанию 1000) →
     «база без ограничений» (туда можно спокойно писать). Если участников меньше —
     попадает в отдельную базу «мало участников».
4. Все базы можно посмотреть в боте списком (раздел «🗂 Базы»).
5. Можно остановить парсинг и запустить **перепроверку** базы «без ограничений» —
   бот заново проверит, не появились ли там ОП/капча.
6. Если очередь опустела — приходит уведомление и парсинг останавливается.
   Пока очередь не пуста, парсинг идёт сколько угодно.

Парсинг идёт **по очереди с паузами** (`CHECK_INTERVAL`), чтобы не словить лимиты
Telegram (FloodWait). Это не мгновенно — и так задумано.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполнить API_ID / API_HASH (с https://my.telegram.org)
```

## Запуск

```bash
python -m parser_bot
```

## Настройки (`.env`)

| Переменная       | Назначение                                              |
|------------------|---------------------------------------------------------|
| `BOT_TOKEN`      | токен управляющего бота                                  |
| `ADMIN_ID`       | id админа (только он управляет ботом)                    |
| `API_ID`/`API_HASH` | данные приложения Telegram для входа в аккаунт        |
| `MIN_MEMBERS`    | минимум участников для базы «без ограничений» (1000)     |
| `CHECK_INTERVAL` | пауза между проверками чатов, сек (анти-флуд)            |
| `PROBE_WAIT`     | сколько ждать ответ модератора после точки, сек          |
| `DB_PATH`        | путь к файлу SQLite                                       |

## Базы (статусы)

- **Без ограничений** — чисто, участников ≥ лимита (можно писать).
- **Плохая база (капча)** — обнаружена капча/антибот.
- **ОП проверенные** — у чата была обязательная подписка, список ОП обработан.
- **ОП непроверенные** — каналы из списков подписки, ждут проверки.
- **Мало участников** — без ограничений, но участников меньше лимита.
- **В очереди** — ждут проверки.
- **Ошибки доступа** — не удалось проверить (приват/бан/флуд).

## Замечания

- Детект капчи/ОП — эвристика по ключевым словам и кнопкам ответа модератора.
  Списки слов настраиваются в `parser_bot/config.py`.
- Аккаунт вступает в проверяемые чаты (иначе нельзя писать/считать участников) —
  это расходует лимиты Telegram, поэтому интервалы важны.
- Деплой на сервер (например, по предоставленному IP) — обычный `python -m parser_bot`
  под systemd/screen/tmux. Секреты держите в `.env`, а не в коде.

## Структура

```
parser_bot/
  __main__.py   точка входа, связывает всё вместе
  config.py     конфигурация из .env
  database.py   SQLite: чаты и их статусы
  userbot.py    Telethon: вход в аккаунт + проверка чата (точка/ОП/капча)
  crawler.py    очередь, интервалы, режим перепроверки
  bot.py        интерфейс управляющего бота (aiogram)
  utils.py      разбор ссылок на чаты
```
